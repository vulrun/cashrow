# Data model

Everything lives in one Google Sheet in the user's Drive. The layout below is a contract: existing users'
spreadsheets depend on it. Change it only in backwards-compatible ways (see `AGENTS.md`, rule 2).
The code that encodes this layout is `src/backend/layout.ts` and `src/backend/mappers.ts`.

## Spreadsheet

- Created by the app with the name the user chooses. With the `drive.file` scope the app can only open
  spreadsheets it created itself.
- Tagged with the Drive app property `cashrow=1` so the setup screen can list it.
- Contains one `__Settings` tab plus one tab per party. Other tabs are ignored, so users can add their
  own sheets (charts, notes) freely.

## `__Settings` tab

| Cell / row | Contents |
| --- | --- |
| `A1` | Global settings as JSON (below) |
| `A2` | A note for people reading the sheet |
| Row 3 | Registry header (bold, frozen) |
| Row 4+ | One row per party |

Registry columns:

| Col | Header | Example | Notes |
| --- | --- | --- | --- |
| A | Party ID | `pty_k3j9x2m1q0` | Stable id generated by the app |
| B | Tab ID | `1849302211` | The party tab's `sheetId` (gid). Survives renames |
| C | Name | `Sharma Traders` | Kept in sync on rename; the live tab title wins |
| D | Status | `active` / `archived` | Archived parties have their tab hidden |
| E | Created At | `2026-05-28T09:00:00.000Z` | ISO timestamp |
| F | Archived At | `2026-11-02T10:15:00.000Z` | Empty when active |

Global settings JSON (`__Settings!A1`):

```json
{
  "schemaVersion": 1,
  "currency": "INR",
  "dateFormat": "text",
  "paymentMethods": ["UPI", "Bank transfer", "Cash", "Cheque", "Card"],
  "allowFutureDates": false,
  "balanceWording": "net",
  "sidebarTotals": "balances"
}
```

| Key | Values | Default |
| --- | --- | --- |
| `currency` | ISO 4217 code; the UI offers INR, USD, EUR, GBP, AED, SGD, AUD, CAD | `INR` |
| `dateFormat` | `text` (23 Oct 2026), `dmy` (23/10/2026), `mdy` (10/23/2026), `iso` (2026-10-23) | `text` |
| `paymentMethods` | non-empty list of names, 30 characters max each | five defaults above |
| `allowFutureDates` | boolean | `false` |
| `balanceWording` | `net` (Net in / Net out) or `settle` (You'll give / You'll get); display only | `net` |
| `sidebarTotals` | `balances` (balances to settle, by direction) or `cash` (You got / You gave); display only | `balances` |

Settings are parsed leniently: a missing key, bad value or broken JSON falls back to the default
instead of breaking the app. People never edit this JSON in the app; the Settings dialog has form fields.

## Party tab

One tab per party, titled with the party name.

| Row | Contents |
| --- | --- |
| 1 | `A1`: party settings JSON (below) |
| 2 | Insight labels: Total in · Total out · Balance · Entries · Last entry |
| 3 | Insight formulas (for people reading the sheet; the app computes its own totals) |
| 4 | Empty (keeps the entry table separate for `values.append`) |
| 5 | Entry header (bold, frozen) |
| 6+ | Entries, appended at the bottom |

Entry columns:

| Col | Header | Stored as | Example |
| --- | --- | --- | --- |
| A | Date | text `YYYY-MM-DD` | `2026-10-18` |
| B | Type | `IN` (you got) or `OUT` (you gave) | `IN` |
| C | Amount | positive number, 2 decimals max | `8000` |
| D | Payment Method | text | `Cash` |
| E | Notes | text, 500 characters max | `Part payment, invoice #1120` |
| F | ID | text, hidden | `ent_4hd8s0q1zm` |
| G | Created At | ISO timestamp, hidden | `2026-10-18T10:00:00.000Z` |
| H | Updated At | ISO timestamp, hidden | `2026-10-18T10:00:00.000Z` |

Row 3 formulas:

```
A3  =SUMIF(B6:B,"IN",C6:C)
B3  =SUMIF(B6:B,"OUT",C6:C)
C3  =A3-B3
D3  =COUNTA(F6:F)
E3  =IFERROR(INDEX(SORT(FILTER(A6:A,A6:A<>""),1,FALSE),1),"")
```

Party settings JSON (`A1`):

```json
{
  "schemaVersion": 1,
  "partyId": "pty_k3j9x2m1q0",
  "name": "Sharma Traders",
  "phone": "+91 98300 41275",
  "email": "",
  "defaultPaymentMethod": "UPI",
  "notes": "GSTIN 19ABCDE1234F1Z5",
  "createdAt": "2026-05-28T09:00:00.000Z",
  "outLabel": "",
  "inLabel": ""
}
```

`outLabel` and `inLabel` rename the two entry types on this party's screens only (e.g. `You paid` /
`You owe`); 20 characters max, empty means `Cash out` / `Cash in`. They are display only: the Type column
still holds `IN` / `OUT`, and a missing key reads as empty.

## How values are written and read

- Entries are written with `valueInputOption=RAW`, so text such as `=IMPORTXML(...)` in a note stays
  text and is never executed as a formula.
- Values are read with `UNFORMATTED_VALUE`. Dates typed by hand into the sheet come back as serial
  numbers and are converted. Type accepts `IN`/`OUT` and a few synonyms (`cash in`, `got`, `gave`...).
- Rows with an unreadable date, type or amount are skipped and reported on the party page.
- Rows without an ID get a temporary `row-N` id and a real one the first time they are edited.

## Operations

| Action | What changes in the sheet |
| --- | --- |
| Create spreadsheet | New file with `__Settings`; Drive app property set |
| Open from Drive | Adds `__Settings` if missing; nothing else is touched |
| Add party | New tab (rows 1 to 5, columns F:H hidden) + registry row, in one atomic request |
| Edit party | Tab renamed if the name changed; `A1` JSON and registry row updated |
| Archive / restore | Tab hidden / shown; registry Status and Archived At updated. Nothing is deleted |
| Add entry | One row appended under the table |
| Edit entry | That row rewritten in place, after checking ID and Updated At |
| Save settings | `__Settings!A1` rewritten |

## Versioning

`schemaVersion` is `1` in both JSON blobs. If a future change is not backwards compatible, bump it,
teach the parsers to read both versions, and migrate on load (write the new version back). Never
remove or reorder existing columns; append new ones after column H.
